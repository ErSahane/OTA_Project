# Naming Conventions

## General Rules
- Use descriptive and consistent names.
- Use lowercase for code artifacts and directories where appropriate.
- Use PascalCase for classes and types.
- Use camelCase for methods and variables.
- Use kebab-case for file names and route segments.
- Use UPPER_SNAKE_CASE for constants and configuration keys.

## Domain Naming Examples
- services/booking
- services/payment
- components/search-results
- models/booking-request
- repositories/booking-repository

## API Naming Rules
- Use nouns for resources.
- Prefer plural names for collections.
- Use clear action names for operations that are not CRUD-based.
- Keep endpoint names predictable and versioned.
