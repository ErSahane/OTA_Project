# Git Workflow

## Overview
Use a disciplined Git workflow to provide clear change history, efficient collaboration, and release confidence.

## Workflow Principles
- All changes go through feature branches.
- Pull requests are required before merge.
- Main branches remain stable and releasable.
- Changes are reviewed by at least one qualified reviewer.

## Standard Flow
1. Create a feature branch from the main branch.
2. Implement changes with supporting tests and documentation.
3. Open a pull request.
4. Review, approve, and merge.
5. Deploy through the approved CI/CD process.

## Commit Standards
- Use clear and descriptive commit messages.
- Keep commits focused on a single concern.
- Avoid mixing formatting-only changes with functional changes.
